> 所有者要求：仿真场景要**用真机跑通过的那次**来定义，不要自己重新设计。
> 本文把 2026-10-20~24 的工作日志与 49 条真机轨迹里**能直接约束仿真**的事実抽出来，
> 每条都标了出处。仿真代码/模型与之冲突时，**以本文为准**。

## 4. 碰撞处理（真机试过五条路，结论明确，仿真照抄）

```text
1. attach + touch_links（师兄做法）        → 可用（位姿查询显示 identity 但实际有效）
2. 手工下发 ACM                            → 破坏 SRDF 默认豁免，不用
3. 世界系实心 mesh 跟随 TCP                → 与腕部自碰撞
4. 点云体素模型                            → 几何真实，仍可能自碰撞
5. 体素 + 挖空夹爪通道                     → 能过但模型失真，**禁止使用**
正解：师兄 attach 节点 + 插入段移除插槽碰撞体
```

- 出处：`2026-10-22_HANDOFF_EVENING_UNLOAD.md` §四"碰撞建模"。
- **插入时插槽碰撞体是从规划场景里移除的**（`20261022_full_task_e2e/meta.json`: `slot collision removed during insertion`）。
  所以我们的 `NO_COLLISION_CHECK_PHASES` 不是取巧，是照抄真机做法。
- **工件抓取后是 attach 跟随工具**，不是留在场景里当碰撞体
  （`workpiece collision via senior attach`）。
- MoveIt **不检查世界↔世界**，所以"把工件作为世界盒子来校验"永远无碰撞——错误方法；
  校验一律用 `check_state_validity`。
- 真实教训：接近插槽时用"简化碰撞网格（无扶手）"导致余量不足、差点碰撞
  → 碰撞体必须**带扶手**（这正好是本次仿真模型要修的东西）。

## 5. 速度与分段（真机实测，比我们现在的配置更快）

| 场景 | 真机实测 | 出处 |
|---|---|---|
| 装入（非装配段） | planning 0.01，time_scale 2.0–3.0，每段 40–50 mm，停 1 s | 卸载 handoff §四 |
| 抽出（装配段） | planning 0.01，time_scale 5.0，每段 **10 mm**，停 **1.5 s** | 同上 |
| 插入/抽出通用基准 | planning 0.005–0.01、time_scale 3.0–5.0、每段 10–20 mm、停 1.0–1.5 s | 10-23 handoff §4.5 |

## 6. 夹爪（HITBOT EFG80，外撑式）

```text
· 夹持宽度 50 mm + 电流 0.1 A（50 mm 已完全顶住；52 mm 起电源 ~1 A 硬顶）
· init 约 10 s，必须等到 init==5 才能发下一条命令
· 归零有偏移：显示开度 ≠ 真实开度；寄存器 70 电流反馈不可信，以电源面板为准
· 无自锁：保持夹力 = 持续通电（有电流声是正常的）
· 释放夹爪必须所有者当次授权（曾发生未授权松开、工件悬空险坠）
```

出处：10-23 handoff §4.4、10-22 卸载 handoff §四。

**外撑几何（口径必须分清，容易混）**：

```text
夹爪开度（EFG80 行程）     = 50 mm          ← 硬件事实，所有者确认
连杆把行程换成两臂外撑跨距 = 204.00（全闭）→ 246.57 mm（全张）
比值                       = (246.57-204.00)/50 = 0.8514 mm 跨距 / mm 开度
URDF 关节建模的是          = 单侧垫块位移 0 → 21.285 mm（不是夹爪开度，也不是跨距）
两个扶手内侧间距           = 233 mm（CAD）
grasp TCP（零件系）        = (-0.3235, 0.0829, 0.1793) m，离扶手凹槽底面 26.8 mm
```

**说"夹爪张开到 246.57 mm"是错的**——夹爪只张 50 mm；246.57 mm 是两根支撑臂的外撑跨距。
仿真碰撞体必须复现**扶手凹槽**（223.8 mm 自由跨度），不能是实心块。

## 7. 五条必须搬进仿真的"铁律"

```text
1. 释放后：先初始化手指 → 纯平移沿插入轴离开 ≥150 mm → 才允许旋转（曾在槽内旋转导致急停）
2. 中止后只允许重新规划，禁止重放旧轨迹（曾导致来回抽搐）；
   规划请求不要填 start_state，让 MoveIt 用自己的实时状态
3. 执行器首点保护：与当前位置偏差 >0.03 rad 拒绝执行（防"先跳回再前进"）
4. 带工件进出插槽一律走 staging 高位；不允许中途点直达
5. 释放夹爪必须当次授权；单个动作 ≤60 s，60 s 无位移立即排查
```

出处：10-23 handoff §5、10-22 卸载 handoff §三。

## 9. 10-20 / 10-21 两天的经验（补读）

### 9.1 碰撞场景里曾经放了什么（10-21）

```text
box_collision / slot_collision / slot_table（草稿 bbox）/ workpiece_table（草稿 bbox）
草稿桌面：workpiece_table center 0.60,0.925,-0.15 size 0.90,0.75,0.10
          slot_table      center 1.175,0.225,-0.11 size 0.55,0.45,0.10
```

**草稿 bbox 后来成了抓取失败的直接原因**：`20261022_table_removal_test` 实测
"去掉两张桌子后 pre-grasp→grasp 的规划 fraction 从 0.72 变成 1.0"，
结论是 `draft table collision boxes are the blocker; calibrate table bboxes before grasp`。
我们在仿真里用的桌子是点云拟合值（不是草稿），这一点已经比当时好，但**仍然要按实测校准**。

同一份日志还写着：`绿色是碰撞体；视觉 GLB 才有完整扶手` ——
也就是说**当时碰撞体缺扶手、视觉模型有扶手**，这正是后来"接近插槽差点碰撞"（急停）的原因。
本次仿真模型（body + rail）就是把这个缺陷补上。

### 9.2 环境扫描的做法（10-21）

RVS E1 逐视角采集 PCD → 7 个视角合并（1 cm 降采样，29,484 点）→ 体素化成桌面碰撞体。
已知不足：**没有做机器人自点过滤**，覆盖率未验收。

### 9.3 长轨迹必须切段（10-21）

实测：`pre-grasp → grasp 120 mm` 拆成 2 段（每段 1.9 s）后 feedback 误差为 0；
而 12.4 s 的整段长轨迹出现**执行层超调**（controller 参考已到目标、实际反馈越过）。
→ 仿真里也应该按"短段 + 逐段验收"验证，不要用一条长轨迹下结论。

### 9.4 关节顺序只能按名字（10-21 已经写过，本次又踩了一次）

`2026-10-21_WORKLOG_PLANONLY_CARTESIAN.md` L20：
"**不能按位置数组下标直接当 standard 关节顺序**；所有分析和数据记录必须按 name 映射。"
本次仿真里 IK seed 用 `/joint_states` 原始数组导致整段错位，就是这条的复现。

## 10. 坐标约定：三个 frame 必须分清（10-20 日志的第一条经验）

10-20 的日志把它列为"最重要的经验"：**两个约定偏移不写进模型，一切分析都是假的**。

```text
① 法兰 → 工具 TCP：(-46, 0, 353) mm      ← 10-20 师兄工具的实测（actual_tcp_offset_* 一致）
② 工件模型原点 → 几何中心：box.ply 尺寸 131 x 430 x 222 mm，中心偏移 (10.5, -215, -105.2) mm
   （T_b_tcp 平移 (-4, -215, -411) mm；按中心输出则 T_center_tcp ≈ (-14.5, 0, -305.8) mm）
```

这两条分别造成过 **353 mm** 和 **约 16 cm** 的系统偏差，且两次都被先误判成"视觉算错 / 手眼标定错"。

### 10.1 当前仓库里的状态（需要注意的一处不一致）

```text

  （X ±147.285、Z -7.0..+207.0 mm），flange→my_end_effector_link 为零偏移，

  并且 T_tcp_cam = inv(T_flange_tcp) @ T_flange_cam_color_optical。
  URDF 里 camera_color_optical 相对 my_end_effector_link 只有 (0.0970, 0.0422, 0.0975) m，
  即相机离 eef 约 0.14 m；而 T_tcp_cam 的平移是 0.296 m —— 两者相差约 0.16 m。
```

数值对比（用 baseline 位姿 `1.044,-0.011,0.726`、四元数 `[-0.059,0.938,0.060,0.336]`，

| 组合 | 相机位置 | 到槽心距离 | 光轴与"相机→槽心"夹角 |

**这条必须在真机上一次性验明**，方法（不需要机器人运动）：
