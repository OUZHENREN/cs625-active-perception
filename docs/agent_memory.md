## 1. 铁律 / 工作方式

原 §1 的规则（全部照旧）：

- 先 plan-only，确认后再执行。
- 不跑 100% 速度；低速、分段、每段看 feedback/TCP。
- 急停后人工确认安全，再恢复；不自动续跑。
- 不用未文档化的 raw TCP 运动；能用官方/师兄接口就用。
- 保留有意的 120 mm pre-grasp 偏移。
- 装配动作（抓取、插入、取出）：time_scale ≥ 5.0，规划速度 ≤0.025，段间停顿 ≥1.5 s；插入更慢。
- 装配按小段执行，每段停、读 feedback/TCP，再走下一段。
- 真实和仿真 profile 分开，不混用。

所有者工作方式要求（原 §4，2026-11-04，必须遵守）：

- **所有者工作方式要求（2026-11-04，必须遵守）**：所有者明确指出"需要改代码"的漏洞，
  当轮就要顺手修掉并提交，不要记到待办里延后——延后必然遗忘，且会让所有者重复提同一条。
  已经因此重复过的例子：预抓取竖直接近（只手工做过、没写进代码）、抓取段速度过快、
  抓取位到位容差过松、门检失败不纠偏。凡是"质量标准"类要求（速度、容差、核验），
  都要同时写进本文件或 manuals 手册，避免只存在于代码注释里。

## 2. 安全红线（原 §132–§138 的核心；事故经过与原文见 history）

> 事故代价（原 §135 开头）：夹爪与机械臂碰撞导致 J4 轴信号中断、机器人无法重启；
> 另一次夹爪撞到机械臂本体，机器人进入 safety_mode=9(FAULT) / robot_mode=3(POWER_OFF)。
> 这不是"一次失败的规划"，是可能损坏设备、危及人员的事故。

**① 抓取前看自碰撞，抓取后看附着工件（原 §132）**

- 未抓取到工件之前：TCP 基本不需要用来判断碰撞；这个阶段最容易碰撞的是**自碰撞**——
  夹爪的电机保护座末端与机械臂自身伸出的夹爪。
- 抓取到工件之后：主要考虑**附着在夹爪上的工件**会不会撞到环境/夹具；这时 TCP 才需要认真检查。
- 之前把"自碰撞"错记成抓取之后的风险，实际顺序相反。

**② 绝不为"让规划通过"而屏蔽碰撞信号（原 §134 / §135-1）**

- 任何接触对都不允许忽略；检查到接触就拒绝该轨迹，不管它看起来多像"邻接造成的假阳性"。
- 怀疑是模型邻接问题，正确做法是改 URDF/碰撞矩阵的 disable_collisions，而不是在运行时的
  检查里放过——前者是配置修正，后者是拿安全换通过率。
- 自碰撞多发生在：夹爪电机保护座末端 ↔ 机械臂本体、手腕大角度时的法兰 ↔ 前臂。

**③ 已接触不许动（原 §135-2）**

- 移动前必须先检查【当前状态本身】：`/check_state_validity` 若报告任何接触 →
  立刻停手并报告所有者，不得规划任何移动。
- 这次就是"当前状态已接触"被当成假阳性继续规划，才酿成碰撞。

**④ 禁止翻转构型（原 §133 / §139⑥）**

- 选 IK 解时不能只看"腕部变化最小"，必须看整条手臂的关节变化——取"离当前构型最近"的解。
- 明确拒绝：`|wrist_3| > 170°`；J2 过低且肘伸展 >100°；shoulder_lift 低于 5° 且 elbow
  大角度伸展（即"手臂横伸到桌面高度"这一类）。
- 任何大幅改变构型的移动（腕部 >45°、肩转变化 >30°、或整臂关节变化 >1.5 rad）：
  必须先打印 6 个目标关节角与预计轨迹时长，得到所有者明确同意后才执行。
- 一次运行中最多做 1 次"试探性移动"；失败即停，不得连续试错。
- 腕部接近 ±45°、手臂接近折叠、或 TCP 距离本体 <0.25 m 的构型，视为危险，执行前必须人工确认。

**⑤ 各关节建议约束角（真机，原 §136）**

| 关节 | 建议安全范围 | 危险/禁止 | 原因 |
|---|---|---|---|
| J1 肩转 | −100° … +100° | \|J1\| > 120° 的"绕到另一侧" | 换构型，易让肘/腕贴近本体 |
| J2 肩抬 | −75° … −20° | 接近 0°（手臂水平）且肘伸展 | 手臂横伸到桌面高度，会撞桌子 |
| J3 肘 | −150° … −100° | < −160°（几乎折叠） | 前臂贴近上臂，自碰撞风险 |
| J4 腕1 | −120° … +120° | \|J4\| > 180°（如 293°） | 线缆缠绕，本次事故即 J4 信号中断 |
| J5 腕2 | −120° … +120° | \|J5\| > 150° | 腕部姿态极端，接近奇异 |
| J6 腕3 | −150° … +150° | \|J6\| > 170° | 电机/相机线缆缠绕（业主明确） |
| TCP（抓取前） | z ≥ 0.30 m（工件附近） | z < 0.15 m 且手臂伸展 | 贴近桌面/夹具 |

- 抓取前不考虑 TCP 与工件的"碰撞"，但上面的关节区间与 TCP 高度仍然适用；抓取后要额外
  检查"附着工件"与环境的干涉；任何一次移动前，规划器必须检查【当前状态】不处于接触状态。

**⑥ TCP 是虚拟点：空载约束工具实体前端（原 §4，2026-11-03）**

- 未抓取工件时，TCP 比实际工具实体前端还远 146 mm（法兰→TCP 353 mm，法兰→工具前端 207 mm）。
- 空载摆位/观测的约束对象是**工具实体前端**（法兰 + 207 mm 沿工具 z），不是 TCP；
  用 TCP 卡碰撞相当于白让出 146 mm 高度，会把观测位逼得又远又平。已抓件时才按 TCP + 携带盒约束。

**⑦ 持件速度上限（原 §139②）**

- 夹爪夹着工件时，任何动作巡航速度受 `CARRY_SPEED_CAP = 0.013` m/s 硬约束
  （代码在 `scripts/teaching/teaching_sequence.py:212`）。
- 当前 SPEED 表：lift 0.012、transit/staging 0.013、pre_insert/withdraw 0.012，
  插入段 0.002（槽内 1–2 mm 间隙），straighten 0.1，time_scale 2.0。
- 旧条目的 0.020/0.015 已作废；所有者已多次指出"太快"。

**⑧ 工件附近必须先抬升/后撤（原 §4，2026-11-05 险情）**

- 低高度时禁止"横向为主"的移动，必须先竖直抬到 `SAFE_HEIGHT_Z = 0.53` 或沿工具轴后撤。
- 关节空间直线不等于笛卡尔直线，关节插值会让末端走弧线并扫过工件；
  代码已用 `lift_before_lateral()` 强制，勿绕过。

## 4. 相机与视角约束（架构级，原 §137；观测位定调原 §138）

- 相机安装位置：TCP 系 (0.143, 0.042, −0.255)——在法兰后再伸出约 0.3 m（TCP 后方 296 mm）。
- 转动手腕时，相机不是"原地转"，而是被甩出一个半径约 0.3 m 的大圆弧；这就是"转动毫无意义、
  伸出端差点撞上"的根本原因（所有者 2026-11-13 多次指出）。
- 换视角优先【平移】（前三轴带整臂移动），保持工具姿态基本不变。
- 禁止为了"凑视角"去转 J6 或大幅度转 J5：相机扫过的空间比你想的大得多，而且转腕本身对视角的
  贡献很小（真正改变可见性的是相机的位置）。
- 需要改变观察方向时，改变量应等于工件的转角（例如工件转 +13°，相机方向也只转 13°），
  而不是让 IK 去挑一个"另一个分支"的解。
- 判断依据：若某个视角的 IK 解需要 J5/J6 变化 > 30°，说明视角推导或站位有问题，应先停。
- 腕部接近 ±45° 视为危险构型（原 §135-4）；`|J4| > 180°` 会线缆缠绕（本次事故即 J4 信号中断），
  `|J6| > 170°` 会电机/相机线缆缠绕（原 §136）。

观测位策略的最终定调（原 §138，所有者决定）：

- 工件粗观测位：沿用当前固定位姿（示教 workpiece_coarse），不再为它做 NBV 或重新标定。
- 插槽观测位：粗观测与精观测位置基本固定，**插槽不需要 NBV**；插槽测出的位姿主要用于"比对"
  （判断夹具是否变化），不直接参与后续运动。
- NBV 的适用范围收窄为：仅在"工件精观测视角不合适"时使用，并且只做小幅平移微调（不转腕、
  不改构型），大幅调整交人工。

### 硬件损伤事故（2026-11-13 → 11-14 确认）

```text
自动转动机械臂 → 夹爪与 J4 部位自碰撞并卡死 → 拆夹爪才取出。
后果：J4 抱闸失效（断电后该轴可自由摆动，伴蜂鸣）。
⇒ 规则：自动换位/大幅改构型前必须确认"工具与腕部不会自碰撞"；
  规划能过 ≠ 不会撞（规划场景里没有工具与腕部的精细碰撞体）。
⇒ 详情见真机手册第 30 条。
```
