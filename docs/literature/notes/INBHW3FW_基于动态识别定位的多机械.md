## 2. 一句话结论与相关性
- 一句话：为"机器人在垄间**连续行走**、边走边采"的草莓收获场景，做了三组 2 自由度机械手 + 双目视觉 + 集中式控制的样机；核心贡献是把**相机曝光信号触发运动控制卡高速锁存本体位置**，解决"视觉信息滞后导致图像与位姿在时间上不一致"和"视觉反馈频率低"两个问题，再用**运动恢复结构**补深度；室内试验在行走速度 **60/80/100 mm/s** 下动态定位误差均 **<0.5 mm**、采摘率 **100/100/96.7%**、最快 **1.7 s/次**（[原文证据] p.4、p.90、p.91）。
- 相关性分类：**方法迁移**。理由：对象（草莓）与我们的装配对象毫不相关，但其"**异构频率传感器的时空对齐**"与"**速度—定位误差关系的实测方法**"正好命中我们现有两块软肋——点云/位姿的时效性（我们被明令禁止消费过期点云与过期 joint_states）和"精度只在静止时验证过"。
- 影响本课题的具体决定：**观测动作**（运动中能不能测、测出来对不对）、**验证方式**（要不要做"速度—位姿偏差"扫描）、**定位要求**（哪个速度档以下现有 gate 仍然有效）。

## 3. 对象与任务
- 对象：垄作栽培的成熟草莓果实（红色、贴垄坡、垂直垄坡方向几乎不重叠、上侧偶尔有叶片遮挡）（[原文证据] p.54、p.48）。
- 任务与容差：末端执行器为"拢果式"（从下向上拢起、避开障碍后夹持并切割果柄），试验表明**目标果实定位误差在 ±7 mm 范围内、果实域宽度在 10 cm 范围内**都能完成采摘（[原文证据] p.4、p.93）——注意这个容差比我们的 1–2 mm 间隙宽一个数量级以上。
- 机器人构型：3 组 **2 自由度**采摘机械手 + 龙门式行走机构 + 双目视觉 + 控制系统；摄像机与第一机械手在 X 方向相距 **350 mm**，机械手之间 **400 mm**（[原文证据] p.89）。
- 作业节拍与速度：行走速度分 **60 / 80 / 100 mm/s** 三档；每采完一次，龙门行走机构前进 **500 mm** 进入下一个工作循环（[原文证据] p.54）；100 mm/s 下每米 10 颗密度可完全采摘，**1.7 s/次**（[原文证据] p.91）。
- 传感器：单目手眼系统 + 双目立体视觉（轮廓匹配）；精密运动定位机构 3 个平动自由度；行走机构由伺服电机 + 17 位编码器反馈（[原文证据] p.54、p.49）。无任何力觉/触觉传感器。

## 4. 方法与机制链
- 主链：`局部直方图自动阈值分割（L*a*b* 的 a* 通道）` → `凹点检索 + 边缘局部检测分离相互接触果实` → `双目轮廓匹配定位（世界坐标）` → `手眼视觉伺服只做 X 方向对齐（图像雅可比 + PID）` → `运动恢复结构（SfM）算深度与采摘参数` → `多机械手动态任务分配（遗传算法对照）` → `集中式控制器下发`（[原文证据] p.48–p.51、p.56–p.58、p.84）。
- 关键机制 1（本文最值得抄的一条）：**相机曝光信号 → 触发运动控制卡高速锁存位置**。文中分析机器视觉时序为"曝光 t0 → 读取传输 t1 → 处理分析 t2 → 得到位置、下发命令 t3"，t0 到 t3 有固有滞后；因此在**曝光瞬间**由硬件锁存行走机构在 X 方向的位置 `x_a`，于是"这一帧图像描述的就是 `x_a` 时刻的环境"，图像与位姿在时间上一致；锁存滞后原文写"**25 冲**（OCR 单位，疑为 μs）可忽略"（[原文证据] p.57–p.58）。
- 关键机制 2（低频视觉 + 高频本体状态的融合）：视觉位置 `Δx` 每个 `t` 才更新一次，仍太慢，于是用伺服编码器的高频位置 + 上一次的 `Δu`（像素位移）反算 `x_s = x_a + (Z_c/f)·Δu`，把"图像偏差"变成"高频可更新的世界坐标"，从而实现伺服收敛到目标邻域（[原文证据] p.58）。
- 关键机制 3（遮挡/重叠目标分离）：不直接用凸壳凹点检测（草莓自身有凹陷会漏检），而是"把凹点检测转成凹陷区凸点检测"，用凸包上相邻两点距离阈值找凹陷区，再取凹陷轮廓上点到 `P1P2` 距离小于"最大距离的 1/10"的点集，最后用凹点两侧拟合直线的**角平分线**作重叠边缘方向、沿 a* 梯度图精化分割线（[原文证据] p.49–p.50）。
- 关键机制 4（多机械手任务分配）：把"n 个果实 → m 个机器人"编码成染色体（每个基因取 m 个等位基因之一），适应度取"有效任务分配数量"，用 MATLAB 遗传算法对照；结论是与自提算法"有效采摘任务量相同"，但自提算法的分配更偏向靠前的机械手，理由明确：**行走系统的位置累积误差**使靠前的机械手更容易采到（[原文证据] p.84）。
- 改变了哪个假设（对我的启示）：把"视觉必须先静止再测"改成"**任何时刻都能测，只要把位姿在曝光时刻锁存下来**"（[分析推断]，依据 p.57–p.58）。

## 5. 证据强度
- 动态定位实验（p.89–p.90）：先把行走机构以 **5 mm/s** 慢速前进定位，作为"静态参考值"，再在 **60/80/100 mm/s** 下对同一批果实定位，用 `E_P = |P_ni − P_s|` 算动态误差。结果：果实中心 X 坐标误差 **0.373 / 0.411 / 0.200 mm**，果实宽度误差 **0.327 / 0.267 / 0.183 mm**，果实顶高误差 **0.137 / 0.093 / 0.112 mm**；结论"不同速度下误差无明显差异，均 <0.5 mm"（[原文证据] p.90 表 7-1）。
- **口径问题**：这个误差是"与同一系统在 5 mm/s 下的结果之差"，**不是与真值之差**。若系统本身有系统性偏差（标定、镜头、光照），会同时出现在参考值与动态值里而被抵消；因此 "<0.5 mm" 只能证明"速度不引入额外误差"，不能证明"绝对定位精度 0.5 mm"。
- 采摘试验（p.90–p.91）：**90 颗仿真草莓**（配爬山虎藤作枝叶），分 3 组、每组 10 颗随机分布在 1 m 垄面上，第 3 组有两颗相互接触；三组分别用 60/80/100 mm/s 各做一次，即每个（组, 速度）组合 **n = 1**。结果：采摘率 **100% / 100% / 96.7%**，总用时 **23.7 / 20.3 / 17.7 s**；各机械手成功数 60 mm/s 为 6/4/0、80 mm/s 为 4/4/2（表内为 4/3.7 均值）、100 mm/s 为 4/3.3/2.3（[原文证据] p.91 表 7-2）。
- 失败样本：100 mm/s 下有 **1 颗未采**，作者归因于"局部密度较大、采摘任务没有被完全分配"，**不是视觉失败**（[原文证据] p.91）——这一点很重要：它说明该系统的瓶颈已从"看不见"转到"分不完"。
- 其它口径问题：① "3 机械手"的负载极不均衡（60 mm/s 时第 3 个机械手采 0 颗），说明任务分配算法在实际系统中并未真正生效或机械手布局占优/劣势明显；② 只有 3×1 次试验、且用仿真果实，**真实果实的果柄刚度、叶片遮挡、表面反光均未进入试验**；③ "1.7 s/次"是 17.7 s / 10 颗 的折算，不是单颗计时。
- 结论：作为**时空对齐方法与实验设计**证据可用（机制清楚、时序分析扎实）；作为**精度证据**只能作相对量使用；作为**成功率证据**样本量太小（n=1/工况）。

## 6. 最脆弱的 1–3 个假设
1. "曝光时刻锁存的位置就代表这一帧图像的成像时刻" —— **方法必需**（[原文证据] p.57–p.58，滞后 25 μs 的论证）。分类：**范围外迁移限制**。它的前提是"相机与运动控制卡有硬件触发链路、曝光时间远小于读取时间"；我们的深度相机由 USB/GigE 驱动出时间戳，机械臂是另一套控制器，**没有共享硬件触发**，只能靠软件时间戳 + WSL 时钟（历史上曾倒退 5.5 s，见项目 agent_memory §1.5）。因此其"硬件锁存"的干净解法在我们这里换不来，只能做近似。
2. "视觉算法给出的形心与世界坐标之差在低速段与速度无关" —— **作者明说结论**（[原文证据] p.90）。分类：**尚未测试**。它只在 60–100 mm/s（相当于我们紧间隙段 0.005 m/s 的 12–20 倍）范围内验证过，且用"与静态差值"作指标；本课题 0.10 rad/s 关节速度换算到 TCP 约 0.1–0.2 m/s 量级，仍在该区间内，但我们的相机在 TCP 后方，角速度带来的像面运动是**旋转**而非平移，其结论不能直接外推。
3. "多机械手任务分配决定采摘率" —— **作者归因**（[原文证据] p.91）。分类：**范围内反例**（对其自身数据）：第 3 个机械手在 60 mm/s 时采 0 颗，若真是"分配算法有效"，不会出现某个机械手完全空转；这更像是机械布局导致第 3 臂可达域覆盖差，任务分配只做了"补救"。

## 7. 可迁移到本课题的具体做法
1. **把"点云—位姿配对"做成一条显式链路，而不是隐含在时间戳里**：本文的做法是"在成像时刻锁存位姿"，我们能做的最接近版本是——`cs625_sensor_adapter` 在点云消息的**采集时间戳**上，向 TF 缓冲查询该时刻的 `base_link → camera_depth_optical_frame`，并把"查询到的时间戳差"写进消息/日志，作为**配对质量**字段；`scripts/experiment_recorder.py` 记录每帧配对的时间差。需要：相机驱动时间戳与系统时钟同源（我们已知 WSL 时钟会跳，必须先有"时钟稳定"前置检查）；TF 缓存长度足够覆盖处理延迟。验收：连续 100 帧配对的"点云时刻 − 位姿时刻"绝对值 p95 ≤5 ms，且 `dmesg | grep -c "Time jumped backwards"` 不增长；超过 20 ms 的帧必须被丢弃而不是照用（这与项目"不消费过期点云"的红线一致）。
2. **用高频本体状态外推低频视觉，在"运动中的插入/换位段"也能给出位姿**：本文用编码器高频位置 + 上一帧像素位移重算目标位置。我们的对应做法：在 `cs625_view_evaluation` 的终止判据里，把"连续 N 帧位姿一致"改成"**把每帧位姿按当前关节速度外推到同一时刻后再比较**"。需要：joint_states 频率与相机帧率的比值（我们已记录 joint_states 是高频源），以及一个可靠的关节速度估计（用相邻 joint_states 差分，不引入新硬件）。验收：在 0.005 / 0.03 / 0.08 m/s 三档 TCP 速度下，"外推后比较"得到的位姿与"停稳后重测"的偏差 ≤0.2 mm，且比不外推时小 50% 以上。
3. **补一个我们从未做过的实验：速度—位姿偏差扫描**：本文在 3 档速度下量误差。我们可在"固定站位、固定工件"条件下，让 TCP 以 **0.005 / 0.03 / 0.08 m/s**（对应紧间隙/装配/接近三档）连续运动并同时采集，与"停稳后精拍"的位姿比较，给出偏差—速度曲线。产出直接回答"我们的 gate（slot 1.0 mm / 0.5°）在运动状态下是否还成立"。落点：`docs/reference/` 增加一张表，`docs/evidence/experiment_index.md` 一条记录。验收：三档各 20 组样本，报告均值 + p95；明确指出哪一档开始超出 gate。

## 8. 与本课题现有路线的冲突点
- **与"站位表选站 + 停站精拍"冲突（观测范式层）**：本文是"**不停机连续视觉伺服**"（边走边采，视觉闭环调 X 轴速度），成功的关键是低延迟与硬件同步。我们的真机主线是"停在已验证站位、一次精拍、查表选站"，明确**不做连续伺服**（因为相机在 TCP 后 0.3 m、腕部 ±45° 限制、旋转时相机大幅摆动）。照搬连续伺服会直接触碰我们的两条硬约束：0.10 rad/s 关节速度上限（闭环需要更快响应）与"不消费过期点云"的红线。
- **与"RANSAC 三平面 + CAD ICP"冲突（精度来源层）**：本文用彩色图像分割 + 轮廓匹配 + SfM 深度，接受 ±7 mm 的定位误差，靠**末端执行器的大容差（拢果式、果实域 10 cm）**吸收误差；我们的路线是"高精度位姿 + 1–2 mm 间隙"，容差小两个数量级。这两条路线的哲学相反：它是"**用机械容差换视觉精度**"，我们是"用视觉精度换机械间隙"。**可以借用它的思想，但不能借用它的数值**。
- **与"误差链/公差分配"是补充而非冲突**：本文明确指出"行走系统的位置累积误差，靠前的机器人采摘更利于成功"（[原文证据] p.84），把**长行程移动平台的累积定位误差**列为误差源并据此调整策略。我们 CS625 底座固定、没有行走累积误差，但**站位表换位后的重复定位误差**是同类项，而我们的站位表（`config/tasks/common.yaml:workpiece_views`）里**没有这个字段**——这是被本文照出来的一个漏洞，应在站位表里加"重复定位偏差"实测值。
- **与"导纳式柔顺"无交集但形成对照**：本文全程无力觉（剪切式末端、无接触力闭环），柔顺完全靠**被动机械结构**（拢果、仿形）吸收。我们的插入靠"−10° 倾斜导入 + 0.005 m/s + 导纳式柔顺（effort 残差 0.68/1.63）"。本文证明"如果结构容差做得足够大，可以不做力控"，反过来也提示：我们 1–2 mm 间隙下没有被动容差的余地，**力觉/柔顺是必需的而不是可选的**。

## 9. 待确认
- **锁存滞后的真实单位与量级**："25 冲"经 OCR 后无法确认；若是 25 ms 而不是 25 μs，则"滞后可忽略"的论证不成立，整套时序补偿的收益要重估。
- 视觉系统的**绝对精度**（不是与静态值之差）：无真值测量、无标定板验证、无重投影误差数据。
- 双目基线与工作距离：只写"双目立体视觉"，没有基线长度、焦距、视场、工作距离，无法换算像素当量。
- 图像雅可比 `J_i` 里依赖的 `Z_c`（光心到垄面距离）是"取一个近似值"（[原文证据] p.58），误差有多大、如何标定，未给。
- 三档速度下**每种速度只有 1 组 10 颗**（n=1）；失败样本 1 个且归因于任务分配，缺少"视觉失败"与"分配失败"的分类统计。
- 试验果实为**仿真草莓模型 + 爬山虎藤**（[原文证据] p.90），真实果实的果柄刚度、叶片遮挡、表面反光对分割与定位的影响未验证。
- 三个机械手的成功数极不均衡（60 mm/s 时 6/4/0），但正文没有分析机械手 3 为何空转——是可达域、任务分配、还是时间窗冲突，未给证据。
