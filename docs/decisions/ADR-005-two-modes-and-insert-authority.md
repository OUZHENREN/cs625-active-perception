# ADR-005 两种运行模式与插入位姿权威

- 日期：2026-11-07
- 状态：已采纳
- 取代：六模式（scope × mode）作为日常入口

## 背景

六模式（load/unload/full × safe/efficient）是在"全流程演示"阶段设计的。
2026-11-04 起实际开发收敛到**抓取 + 插入**，六模式入口不再直接使用；
同时插入段的定位权威在 11-05 的实机事故中被迫重新裁决。

## 决策

### 1. 入口收敛为两种模式，跑同一条链路

| 模式 | 入口 | 定位 |
|---|---|---|
| 安全模式 | `scripts/resume_teaching.sh` | 门检全开、静置、fitness、位姿库、失败自动重启并续跑；用于演示与取数据 |
| 效率模式 | `scripts/teaching/teaching_debug.py` | 分阶段、可改参数、自动归档；用于十一月视觉开发与十二月力控实验 |

六模式源码（`run_task.py`、`run_pick_and_place.py`、`cs625_ui.py`）**冻结保留**，
不删除、不再作为入口。

### 2. 插入位姿权威 = 记录中人工验证过的位姿

```text
优先级：runtime/slot_reference_verified.json
      → config/tasks/common.yaml 的 teaching_slot_reference
      → 当天 R1（兜底，且会打印警告）
```

**理由**：2026-11-05 当天 R1 与已验证位姿差 33 mm，直接驱动插入导致多次保护/急停；
同一天 RVS 的帧间离散度实测可达 920 mm。实时测量只能用于监视与对比，不能作为插入权威。

### 3. 保留的强制约束（与模式无关）

- 保护停止后不自动重试；连续两次 NO_MOTION 才允许一次自动驱动栈重启；
- 工件附近禁止横向移动，必须先竖直抬升；
- 持件阶段巡航速度硬上限 0.013 m/s；
- 释放动作必须显式 `--allow-release`。

## 影响

```text
· VS Code 任务从 17 个收敛为 5 个（开工 / 安全模式 / 效率模式 / 面板 / 自检）
· 运行时不再依赖 RVS 做插入定位；RVS 退化为"一次性位姿采集 + 交叉校验"
· 失败恢复路径统一为：自动重启驱动栈 → --resume 回到最后成功阶段
```

## 备选方案与为何未采纳

| 备选 | 未采纳原因 |
|---|---|
| 继续用六模式作为入口 | 与当前任务无关，且每次都要选 scope/mode，操作面太长 |
| 插入继续用当天 R1 | 实测偏差 33 mm，直接造成撞槽与急停 |
| 插入用当天 R1 与记录值的平均 | 平均会让两者都不对，且掩盖真实分歧 |
