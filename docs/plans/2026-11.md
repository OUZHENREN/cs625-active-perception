## 1. 一句话目标

把"工件位姿从哪来"从 RVS 黑盒换成**自研、可解释、可量化**的管线，并在真机上给出它的
**精度数字**——不是"能跑通"，而是"多少毫米、重复性多少"。

## 2. 为什么是这个月做这件事（三句话）

1. 真机链已经能跑到预插入，但位姿一直靠 RVS：一次采集 2.2–18.6 s，系统偏置实测 33 mm，
   帧间离散 920 mm，而且与 ROS 相机互斥。它当"离线采样工具"可以，当"运行期传感器"不行。
2. 论文模块 2 要的是可复现的"粗-精分层位姿测量"方法；RVS 是黑盒，写不进方法章节，
   也没法做消融实验。
3. 相机深度只有 0.79 fps（且 1280×960 有效点≈0，实际解算用 640×480），所以本月的产物
   必须是"**采一批 → 离线算 → 给结论**"，不承诺实时视觉伺服。

## 4. 本月的三件交付 + 一件条件性交付

### D1 数据入口与重复性基线（第一周，不动机械臂）

```text
数据流：RGB-D(640×480 深度 + 彩色) → capture 脚本 → runtime/vision_dataset/<stamp>/ → 统计报告
```

落盘格式本月定死，后面所有实验都用它：

```text
runtime/vision_dataset/<stamp>/
  cloud.npy     # N×3 float32，相机光学系，单位 m
  color.png     # 640×480
  depth.npy     # 640×480 float32，单位 m
  meta.json     # 时间戳、相机内参、相机模式、任务名、工件标称位姿、操作者
```

**验收**：同一姿态采 20 组（5 种朝向 × 4 次）后，给出四个数字成表——
深度帧率、有效点比例、平均点距、镀膜面空洞率；并且 20 组点云到中位点云的 RMS ≤ 2 mm。

### D2 粗测量：三平面正交 + 三平面求交（第二周）

```text
数据流：cloud.npy → 三级滤波 → 5 指标区域门控 → RANSAC 三平面
        → 法向统一朝向相机 → 正交校验 + Gram-Schmidt → 三平面求交 → 粗位姿(2–5 mm)
```

- 复用：`scripts/icp_pose_once.py` 里的模板加载与评分口径；平面分割与求交用 numpy 新写，
  不引入 PCL 依赖。
- **验收**：5 种工件朝向（0°/30°/60°/90° + 基准）各 4 组，全部能分割出 ≥2 个相邻有效面；
  粗位姿平移误差 ≤ 5 mm、姿态 ≤ 2°；5 指标逐组留档（planarity / CV / 内点率 / 空洞率 / SNR）。

### D3 精配准 + 翻转消歧 + 角点验证（第三周）

```text
数据流：粗位姿 → 现有 ICP（可换 GICP）→ 相对旋转角 >150° 判翻转 → 角点距离验证(2 mm) → 精位姿
```

- 复用 `scripts/icp_pose_once.py` 的配准与 coverage/IoU 评分；消歧与角点验证新写。
- **验收**：20 组里翻转误判 **0 次**；精位姿重复性 σ ≤ 1 mm；与 RVS 在同 5 个已知姿态上
  对照，自研结果与 RVS 的偏差 ≤ RVS 自身离散（33 mm 量级）。

### D4（条件性）插入段收尾——最多 3 天真机时间

- 只做"复现 + 记录"，不追新功能；判据沿用 `docs/plans/2026-10.md` §6（新鲜 R1、力矩余量、
  保护停止后 60 s 内不重试）。
- **触发条件**：D1–D3 在 11-22 前达标。未达标则整体顺延到十二月，与力控一起做。

## 8. 关键命令（每条在做什么、正常看到什么、失败意味着什么）

```bash
# 1) 装环境：ROS Jazzy → underlay → 本仓库 overlay，三层按固定顺序
source scripts/source_dev_env.sh --full

# 2) 相机体检：不移动机械臂，只测"在不在、什么分辨率、真实帧率"
python3 scripts/camera_mode.py status
```

- `camera_mode.py status` 正常输出里有 `color=ok depth=ok`、`res=`、`fps=`；
  `modeling` 模式预期 **0.7–0.8 fps**（这是**深度**的真实速率，不是故障）。
  若出现 `color=missing` 而 `camera_fps` 仍有值 → 相机在发、订阅端收不到（QoS/大图）；
  若 fps 掉到 0.2–0.4 → 别怀疑相机，先查 Fast DDS 共享内存与大图传输。

```bash
python3 scripts/camera_mode.py fast       # 640×480 仅彩色
```


## 9. 风险与预案

| 风险 | 预案 |
|---|---|
| 偏振片其实没装（或装歪） | 不阻塞 D1/D2：先测"现状空洞率"，把偏振作为并行子任务；增强效果等装好后再测，避免把未验证的数字写进论文 |
| 手眼两套口径未验明 | W1 内用"槽心投影到真实 S0 图、落在槽口中心的链才对"验明；验明前所有中间结果**只报相机系**，不报 `base_link` |
| 深度 0.79 fps 太慢 | 采集脚本一次只等一帧新数据（不缓存旧帧）；20 组 × 5 帧纯采集约 2 分钟，可接受 |
| RVS 与 ROS 相机互斥 | 采集前确认 Windows 端 RVS 已停；否则会一帧都收不到且不报错 |
| 工件朝向影响识别 | 仓库实测：扶手面朝向机械臂时最稳（±45° 窗口）。D1 的 5 种朝向要覆盖这个窗口内外，把"朝向依赖"本身变成一个结论 |
| 真机保护停止 | 沿用规则：停止后 60 s 内不自动重试；连续两次 NO_MOTION 才允许一次驱动栈重启 |
