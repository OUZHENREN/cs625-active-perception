# 位姿口径（相机系 / 对象系 / 内参 / 模板）

> 建立：2026-11-10。目的：把"位姿到底相对什么、内参是哪个分辨率、模板是什么单位"
> 这三件事写成**带证据的约定**，避免重犯六模式那类"原点/中心混用"的系统偏差
> （历史上那一处是约 160 mm 的错误，见 `docs/worklogs/2026-10/2026-10-20_WORKLOG_P4_REALTIME_TCP_POSE.md`）。

## 1. 相机坐标系

```text
frame:  camera_color_optical_frame（ROS 光学惯例：+X 向右、+Y 向下、+Z 沿光轴向前）
单位：   米
来源：   /camera/color/camera_info 的 header.frame_id
```

## 2. 内参（按分辨率！）

2026-11-10 实测（1280×960，modeling 档）：

```text
camera_info: width=1280 height=960  distortion_model=plumb_bob  D 全为 0
K = [931.473, 0, 648.695, 0, 931.595, 449.319, 0, 0, 1]
config/real/camera_intrinsics.json 与之一致（fx 931.473 / fy 931.595 / cx 648.695 / cy 449.319）
数据集 runtime/vision_dataset/*/g*/meta.json 里的 K 也一致
```

**约定**：

- 本月的所有计算只用 **1280×960** 这一档，内参就是上面这组；深度是 `16UC1` 毫米，
  已 register 到彩色，所以**深度和彩色共用同一套 K**（实测两者 `camera_info` 的 K 相同）。
- 畸变全零，反投影时不加畸变校正。
- **换分辨率必须重读 `camera_info`**：640×480 的 fx 约为一半、2560×1920 约为两倍，
  绝不能把 1280 的 K 套到别的分辨率上（尺度会差 2× 或 0.5×）。

## 3. 对象坐标系与模板 STL

模板：`~/cs625_rvs_archive/models_20261023/弹仓_装配导出.STL`（不在 git 里，14 MB）

```text
三角面 276642；顶点坐标是【米】（外形 0.4546 x 0.1310 x 0.4650）
外形   455 x 131 x 465 mm（含扶手：投影图里能看到凸出的 U 形）
bbox    min [-0.4358, -0.0220, -0.2400]  max [0.0188, 0.1090, 0.2250]
bbox 中心相对于【STL 原点】 = (-208.5, +43.5, -7.5) mm
网格不是闭合实体（Open3D 报 not watertight），不能算体积
```

**约定**：

- **对象坐标系 = STL 自己的坐标系**，不做任何重定心；位姿写成 `T_camera_object`。
- 需要几何中心时，用 `bbox 中心 = T_camera_object * (-0.2085, 0.0435, -0.0075, 1)` 换算，
  **不要**假设"位姿原点就是几何中心"。
- 同目录下 `弹仓_aligned_senior.sTL` 的轴被重排过（外形 131 × 454.6 × 465），
  **不要和 `弹仓_装配导出.STL` 混用**；`弹仓.STL` 是同尺寸的降采样版，可用于配准但精度较低。

## 4. 位姿的含义（本项目的定义）

```text
位姿 = T_camera_object：把对象系（STL 系）里的点变换到相机光学系
输出：4×4 齐次矩阵，平移单位米
```

**明确不继承 RVS 的约定**：RVS 输出的是**几何中心**，而旧代码把它当成**模型原点**用，
造成过约 160 mm 的系统偏差。我们自己定义 `T_camera_object`，谁是中心、谁是原点一目了然。

当前 D2 粗测量（`scripts/coarse_pose.py`）输出的是**三平面交点（角点）**，它是中间量，
还不是上面定义的位姿——D2 v1 要做的是把这个角点映射成 `T_camera_object`：

```text
1. 三个可见面的法向 → 旋转 R（Gram-Schmidt，右手系）
2. 交点在对象系里对应某个 bbox 角点（取决于哪三个面可见）
3. 用 bbox 角点在对象系中的已知坐标反解平移 t
```
