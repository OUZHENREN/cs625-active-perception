## 1. 本轮要解决的问题

RVS 的工件粗匹配对"看到哪个面"极敏感。同一个粗观测位姿在某些工件朝向下
秒出结果，换一个朝向就回 `NG,POSE`。本轮把这件事从"现象"变成"可复现的基准 + 可统计的准确率"。


## 6. 所有者本轮的核心结论（写入结论，供后续设计依据）

```text
· 工件在 −60° 以内、几乎任意位置都能被识别
· 但靠近 0° 放置时【识别率大大下降】（不是完全认不出，而是显著变差）

结合此前观测（手册第 14 条）：
· 扶手面朝向机械臂、−45°~0° 区间：识别率约 0.9（历史观测）
· 侧面朝向机械臂：识别率约 0.7，且只在近乎不转时可用
```

**所有者补充**：绝大部分"失败"其实来自采集时工件正在被转动，静态摆放基本都可识别。

**含义**：识别率不是"离位姿多近"的函数，而是"工件呈现给相机的是哪个面、以什么角度"的函数。
0° 附近反而最差，说明当前的 0° 摆放让 RVS 看到的是辨识度最低的那一面/角度组合。

**注意用词**：0° 附近是"识别率显著下降"，不是"绝对识别不了"——这一点对后续划界很重要，
否则会把可用但概率低的区间误判为不可用区间。

## 9. 角度符号约定（± 的定义来源，务必先读）

后续所有"工件 +45°/−45°/−60°"的说法都基于以下约定，缺一不可：

```text
① 参考坐标系：机械臂基座坐标系 base_link
   · 原点是机器人底座中心，X 轴指向机器人正前方（工作台方向）
   · Z 轴竖直向上（ROS REP-103：右手系、Z 向上）

② 正方向：绕 base_link 的 +Z 轴，按右手定则
   · 从 +Z 方向俯视（即从上往下看）时，逆时针（CCW）为正
   · 等价说法：从 +X 转向 +Y 为正（这就是 REP-103 的 yaw 正方向）
   · 因此 −60° = 顺时针转 60°；+45° = 逆时针转 45°

③ 工件角 θ_w（本文件里的"工件 +45°"）：工件绕自身竖直轴的偏转量
   测量方式：取 RVS 报告的工件位姿 S3，把四元数转成 RPY，取 yaw 分量
     from scipy.spatial.transform import Rotation as R
     yaw = R.from_quat(S3_quat).as_euler('xyz')[2]      # 弧度，转度乘 180/pi
   注意：S3 的 box 坐标系不是 CAD 坐标系，两者相差一个固定变换；
        但"相对转了多少"用 yaw 差值即可，不受该固定变换影响。

④ 观测方位角 θ_v（基准位的定义）：相机视线在水平面内的方位
     θ_v = atan2(视线方向 dy, 视线方向 dx)               # 同一 base_link 约定
   已登记的两个基准：
     A: θ_v = 43.2°
     B: θ_v = 88.2° = 43.2° + 45°      ← 工件逆时针多转 45°，观测方位也 +45°
```

**为什么必须写清**：符号约定错 180° 会让"逆时针/顺时针"整套推理反转（本轮就出现过一次：
把基准 B 放到 43.2°−45°=−1.8° 一侧，与期望的 88.2° 正好相反）。以后任何"某角度识别率如何"
的结论，都必须连同这三条（坐标系 / 正方向 / 测量方式）一起记录，否则数据不可复用。
