## 3. 锚点可见性判据（硬约束，不是评分项）

锚点 = 工件正面被切掉的那个角（模型系 `z≈+0.225, y≈+0.109` 角），它是四重对称的唯一判别特征。

```text
可见判据（每个候选视角都要过）：
① 锚点 3D 位置投影后落在画面内，且距边界 ≥ 60 px
② 锚点邻域 60 mm 内的模型点，在深度图上有 ≥ 70% 的实测支撑（遮挡检测）
③ 视线与锚点所在面的法向夹角 ≤ 60°
```

不满足就**丢弃该视角**，不能靠"覆盖率凑分"选回来。

## 4. 与自动化脚本的映射

`scripts/run_pick_and_place.py` 的 13 个阶段与上表对应：

```text
pre_grasp → gripper_init → grip → grasp → lift → transit → staging
→ pre_insert → insert → straighten → release → withdraw → baseline
   V3          —           —      V4     V5     V6       V6       V7        V8       V8       V9        V9        V9
```

V0–V2（观察与定位）目前**不在**该脚本内，需要外部先调用 `icp_pose_once.py` 得到工件位姿，
再把 `pre_grasp/grasp` 写回 `config/pick_place_real.yaml`（配置里的坐标是按 10-22 的工件位置标的，
今晚工件可能移动了 13 mm，必须先重新定位再更新配置）。

## 5. 试运行方案（分段验证，不一次跑全流程）

```text
A 段：--phases pre_grasp
      只验证接近轨迹；录像；人工确认夹爪与工件的相对位置
B 段：--phases pre_grasp,gripper_init,grip,grasp,lift
      关键验证"抓得住、抬得起"；失败即停，不进入搬运
C 段：+ transit,staging
      验证搬运路径不擦插槽/桌子
D 段：全流程（含 insert/straighten/release/withdraw/baseline）
      全程 1 Hz 录像，作为任务阶段训练数据
```

每段开始前：

```bash
# 1) 重新定位工件（当前位姿与配置是否一致）
python3 scripts/icp_pose_once.py --weights <best.pt> --template <CAD> 
# 2) 与 config/pick_place_real.yaml 的 grasp 坐标比对，偏差 >10 mm 就先改配置
# 3) 启动录像
python3 scripts/record_frames.py --out ~/cs625_yolo_seg/datasets/2026-10-25_raw/task --rate 1.0
# 4) 执行该段
python3 scripts/run_pick_and_place.py --config config/pick_place_real.yaml --confirm --phases <段>
```

中止条件（任一触发立即停）：

```text
· 任一阶段 TCP 校验误差 > 5 mm
· 夹爪宽度/电流反馈异常
· 插入阶段轴向偏差 > 2 mm
· 任何 safety_mode ≠ 1
```

## 6. NBV 评估接口（下一轮）

已规划的 V0–V2 是固定序列；NBV 要回答的是"给定当前不确定度，下一个看哪里"。评估用同一套数据：

```text
每个候选视角 i，计算：
  score_i = w1·期望可见面积 + w2·锚点可见(硬门禁) + w3·法向对齐
            - w4·运动代价(关节距离) - w5·碰撞风险
验收：在 V0 给出 3 个候选时，评分最高的 2 个必须能成功定位（ICP consensus PASS 且与真值差 <3 mm）
```

第一版权重建议：w1=1.0, w2=门禁, w3=0.5, w4=0.3, w5=门禁。
