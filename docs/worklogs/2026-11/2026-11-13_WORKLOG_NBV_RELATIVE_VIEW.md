## 2. 11-13 13:xx 规划失败的真实原因（不是工件碰撞）

### 2.1 排查结论

```text

  所以 code 99999 不是"TCP 撞到工件"造成的——我之前的猜测是错的。

  最小也要 84°——超过所有者定的 ±45°（电缆不能拧）。

```

### 2.2 新增工具

```text
scripts/plan_pose_ik.py：IK 求解 + 关节线性插值 + 与 plan_pose_once 相同的安全闸
（腕部 ≤45°、单关节 ≤2 rad、时长、抽样 /check_state_validity）。
用途：OMPL 规划不出但位姿可达时，给出一条确定性的关节轨迹。
```

### 2.3 结论

```text
视角推导（按相对视角跟着工件转）在数学上是对的，
但要求机械臂先处于一个"腕部不别扭"的构型。当前构型与之相差 75–84°，
在 ±45° 约束下无法到达 ⇒ 需要先调整机械臂站位（人工或一次性授权）。
```


## 10. 18:5x 关键发现：不是视角不行，是"分支歧义"——用粗观测先验解决

```text
所有者手动摆了一个方向，问"这样不就能拍了吗？为什么说难"。
实测（不动机械臂，只测量）：
  · 3 平面每次都能识别出来（说明三面确实可见，所有者是对的）
  · 但同一位置不同批次差异极大：有时 2/3 组扶手 0.80，有时 0/5 组（扶手 0.08）
  · 查 chosen 解：错误批次里所有对称候选的扶手分都是 0.08、整体覆盖 0.87–0.92
  ⇒ 多起点落到了【错误分支】（对称翻转解），扶手低分是"解错了"，不是"看不见"。

解决：用【粗观测位姿做先验】，剔除偏离 >40 mm / >15° 的组。
  加先验后同一视角：verdict OK，覆盖率 0.982，平移 0.17 mm，姿态 0.063°，3 组全通过。

⇒ 结论：粗→精的正确用法是"粗位姿当先验筛解"，而不是"各自独立多起点"。
   这也是"2 分钟观测"能成立的关键：粗观测（宽松门）已经给出足够好的先验。
```
