## 8. 11:4x 驱动栈为什么没起来（根因）与修复

### 8.1 根因：VS Code 任务里的 pgrep 匹配到了自己

任务「① 开工 · 真机」里这一行：

```bash
if pgrep -f "ros2 launch cs625_bringup" >/dev/null; then echo "[开工] 驱动栈已在运行"; else ...启动...; fi
```

这个 `bash -c` 的命令行里**本身就包含** `ros2 launch cs625_bringup`（else 分支的启动命令），
所以 `pgrep -f` 匹配到了正在执行任务的这个 shell 自己 → 判定"已在运行" → **跳过启动**，
然后直接 `sleep 45; control_health --activate`，自然什么也没激活。

证据：`runtime/logs/driver_*.log` 今天**一个都没有**（nohup 的重定向会先建文件，说明启动分支根本没执行）；
在本机复现：`bash -c 'pgrep -af "ros2 launch cs625_bringup"'` 的输出就是它自己。

### 8.2 修复（第一次改错了，第二次才对）

第一次把判断改成 `pgrep -f "/opt/ros/jazzy/bin/ros2 launch cs625_bringup"` —— **还是自匹配**：
这个字符串本身也写在任务的命令行里（pgrep 的参数），所以照样匹配到自己。
实测：`bash -c 'pgrep -af "/opt/ros/jazzy/bin/ros2 launch cs625_bringup"'` 输出两行，
一行是真进程、一行是执行 pgrep 的 shell。

最终改成 **括号法**，让模式串本身不出现在会匹配的文本里：

```bash
pgrep -f "[r]os2 launch cs625_bringup"
```

命令行里出现的是 `[r]os2`（带方括号），正则 `[r]os2` 匹配的是 `ros2`，所以任务自己的
shell 不会命中，只有真正的 launch 进程会命中。

### 9.2 D2 粗测量 v0 实现

```text
scripts/coarse_pose.py
  1. 图像空间抠出工件：深度窗 0.55–1.05 m 内最大连通域（桌面/幕布先被排除）
  2. 工件点云上逐个 RANSAC 平面分割（3 mm 内点，最多 8 个面）
  3. 平面去重：法向相似度 >0.92 视为同一个面的碎片，只留内点最多的
  4. 挑"两两正交（|n·n|<0.2）+ 内点最多"的三面 → Gram-Schmidt → 三平面 SVD 求交
  5. 输出角点（相机系，mm）与正交误差、条件数
```

### 9.3 实测结果（20 组）

| 朝向 | 成功 | 角点重复性（x/y/z 极差） | 正交中位 | 最小面内点 |
|---|---|---|---|---|
| rot0 | 4/4 | 6.6 / 3.9 / 6.6 mm | 0.101 | 3616 |
| rotm30 | 4/4 | **2.0 / 0.6 / 0.9 mm** | 0.062 | 8404 |
| rotp30 | **0/4** | — | — | 只有 2 个不同面 |
| rotp60 | **0/4** | — | — | 3 个面，但没有一组满足正交 |
| rotp90 | 4/4 | 8.0 / 2.1 / 4.4 mm | 0.033 | 8424 |

### 9.4 分析

1. **重复性最好的朝向（rotm30）角点极差 2 mm**，说明三平面法本身可用；
   差的朝向（rot0/rotp90）第三面点数少（3.6k），交点噪声大。
2. **rotp30/rotp60 失败是几何原因，不是 bug**：工件转到这两个角度时，
   第三个面几乎侧视（只剩 2 个可用面），三平面求交必然退化。
   这与手册记录的"扶手面朝向机械臂时最稳（±45° 窗口）"一致。
3. 下一步两条路：
   · 两平面的朝向用**叉积**补齐第三轴，位置用 CAD 尺寸约束 → 退化姿态也能出粗位姿；
   · 或用 CAD 模板做一次低精度 ICP 当粗位姿（相当于把 D3 前移半步）。

## 12. 13:0x–13:4x D2 v2：多尺度 ICP + 两平面定向搜索 + 置信门槛

### 12.1 三处改进

```text
① 模板采样确定性：Open3D 的 sample_points_uniformly 不吃 seed，改成按三角面面积
   自己采样（固定 seed=7），消除"同一组数据两次跑出不同结果"的来源
② 多尺度 ICP：对应距离 30 → 15 → 8 mm 逐级收敛，避免停在近立方体的浅局部极小
③ 两平面定向搜索（guided_two_plane）：只有两个可见面时，两个面固定两条轴、
   第三条用叉积，沿自由方向扫平移，用"观测点落在 CAD 附近的比例"粗筛后再 ICP
④ 置信门槛 POSE_MIN_COVERAGE = 0.70：覆盖率低于它的位姿标"不可信"，不当作结果
```

### 13.3 判读


### 13.4 D2 v4 待办

```text
1. 位置约束：用三平面交点（角点）作为位置锚点，ICP 只负责姿态微调——角点重复性实测 2–7 mm，

```

```text

  单视角三平面法能到 2–3 mm，但它的精度上限由「可见面数量与质量」决定，
  而不是由算法细节决定。

→ 这正是主动视觉（NBV）要解决的问题：换一个视角把第三个面看清。
```

## 15. 14:3x D2 结论确认 + D3 v1 首跑

### 15.1 D2 能不能说"通过"？——分两句话说

```text
① 算法通过：在"三个面都清晰可见"的视角，粗配准达到 2.5–2.9 mm / 1.6°，
   覆盖率 0.97–0.99，RMSE 3.5–3.7 mm。这是可复现的定量结论。
② 但"所有视角都通过"不成立：rot0（第三面仅 3300 点）和 rotp30（只有两个可见面）
   达不到 5 mm / 2°。这不是算法没做好，是数据里没有足够约束。
```

为此给 `coarse_pose.py` 增加 `view_quality` 字段：

```json
{"planes": 3, "weakest_inliers": 8624, "unconstrained_axis": null, "verdict": "OK"}
{"planes": 2, "weakest_inliers": null, "unconstrained_axis": 0, "verdict": "NEED_ANOTHER_VIEW"}
```

这就是"什么时候该换视角"的判据——**主动视觉的触发条件**，不再是拍脑袋。

### 15.2 D3 v1：`scripts/fine_pose.py` 首跑

```text
三步：细尺度 ICP（体素 2 mm、阈值 8→4→2 mm）
      翻转消歧（R_flip = diag(1,−1,−1)，正解/翻转解各配一次，覆盖率差 <5% 判有歧义）
      角点验证（模型角点经精位姿变换 vs 粗测量三平面交点，阈值 2 mm）
```

结果（20 组）：

```text
RMSE：2.6–2.96 mm（粗配准是 3.5–4.2 mm）—— 精配准确实把残差降下来了
翻转：18/20 判 normal（翻转解覆盖率多在 0.0–0.05，说明扶手已经把歧义解开了）
角点验证：误差 20–57 mm，远超 2 mm 阈值 —— 说明还有一处对应关系没对齐
```

### 15.3 那个 20–57 mm 的角点误差是什么（下一步要查）

```text
两种可能：
① 粗测量的"观测角点"与其位姿不是同一轮迭代的产物（代码里 corner 在中途被更新过）；
② 观测角点与模型角点不是同一个物理角（三平面交点 vs bbox 角点，在工件有倒角/凹陷时不同）。
下一轮先用"人工核对单组：画模型角点与观测角点在点云上的位置"来定位。
```

## 16. 15:0x 追查 "角点误差 20–57 mm"：两层原因，其中一层推翻了我自己的结论

### 16.1 第一层：细尺度 ICP 在漂

单组（g00_rotm30）实测：粗位姿是**精确自洽**的（模型角点经粗位姿 = 观测角点，差 0.00 mm），
但细尺度 ICP 把位姿挪了 **51.6 mm**，覆盖率从 0.97 掉到 0.87。

原因：工件底面离桌面很近，`reject_with_pose(0.03)` 把桌面点也留了下来，ICP 被它们拖走。
处置：剔点阈值收紧到 20 mm、ICP 起始阈值收紧到 6 mm，并加一道守卫——
**精配准只允许微调：位移 >10 mm 或转角 >2° 就拒绝，保留粗位姿**。

### 16.2 第二层（更重要）：角点锚定对到了错误的 bbox 角

加了守卫之后发现：rotm30 / rotp90 的"角点锚定"位姿，用数据一核对覆盖率只有 **0.16 / 0.12**
（ICP 位姿是 0.98 / 0.99）。也就是说：

```text
anchor_on_corner() 用"旋转最接近"来选 bbox 角点 —— 这个判据是错的。
选错角点的后果是：位姿在同一朝向下非常一致（所以"重复性"看起来很好），
但整体偏一个边长，实际贴合很差。
```

→ **D2 v4 里"角点锚定把 rotm30/rotp90 改进到 2.5/2.9 mm"的结论作废**：
那是"一致地错"，不是"更准"。

处置：锚定之后必须用覆盖率复核，掉超过 0.15 就退回 ICP 平移（已实现）。

### 16.3 修正后的 D2 数字（20 组）

| 朝向 | 覆盖率 | 平移重复性 | 旋转重复性 | 位置来源 |
|---|---|---|---|---|
| rot0 | 0.986 | 12.0 mm | 4.06° | 第三面 4703 点 <5000，不锚定 |
| rotm30 | 0.974 | **2.7 mm** | **1.58°** | 锚定被数据否决 → ICP 平移 |
| rotp30 | 0.877 | 19.3 mm | 0.92° | 两面，沿轴 0 无约束 |
| rotp60 | 0.871 | 8.0 mm | 2.34° | 两面，沿轴 0 无约束 |
| rotp90 | 0.978 | 6.8 mm | 2.86° | 锚定被数据否决 → ICP 平移 |

### 16.4 结论

```text
1. 覆盖率（观测点落在 CAD 上）是唯一可靠的"位姿对不对"判据；
   任何"几何上应该更准"的约束（角点锚定、法向拧正）都必须用它复核，否则会自欺。
2. 角点锚定要真正可用，必须先解决"哪个 bbox 角"的对应问题——
   用数据拟合（覆盖率）而不是旋转相似度来选。
3. 更根本的解法：粗测不需要那么准，RVS 的做法是"粗测 → 算出精观测位 → 移动 → 精测"，
   即用视角补偿信息不足（见下一节）。
```

## 18. 15:5x 手眼精度验证：棋盘格脚本 + 离线自测

所有者提供了标定板规格 **Q12-340-25**（12×9 格、格距 25 mm、外形约 340 mm），
对应 11×8 个内角点。

新增 `scripts/verify_handeye_board.py`：

```text
单帧：  --record A      检测 11×8 内角点 → solvePnP → 相机系板位姿 + 重投影 RMS
两姿态：--consistency A B   板在 base 系不动 ⇒ T_base_cam(A)·T_cam_board(A)
                            必须等于 T_base_cam(B)·T_cam_board(B)，差值是手眼+TF 综合残差
```

**离线自测**（合成棋盘：已知位姿投影成图再检测回来）：

```text
重投影 RMS 0.22 px
恢复平移误差 0.18 mm，旋转误差 0.010°   ← 在正确的板坐标系约定下
```

**踩到并记下的坑**：板坐标系原点必须定义为"第一个内角点（左上）"。若把原点当板外形角点，
会正好差一个格距对角线 √2×25 ≈ 35 mm——第一次离线自测就出现了 35.18 mm 的假误差。

## 19. 16:0x–16:2x 手眼精度实测：两姿态 + 旋转一致性，残差 **0.7 mm**

### 19.1 现场过程（机械臂真实运动，所有者在场）

```text
A：当前位姿（TCP 0.563, 0.297, 0.787）拍板 → 重投影 RMS 0.05 px
B：TCP 上抬 50 mm（0.563, 0.297, 0.837）拍板 → RMS 0.06 px
C：原地绕工具 z 轴旋转 +15° 拍板 → RMS 0.07 px
```

`move_tcp_linear.py` 增加了"原地旋转"模式（第 7 个参数 ROTATE_DEG），
用同一个 compute_cartesian_path + execute_assembly_chunks 执行链路。

### 19.2 一致性结果

| 比较 | 运动 | 平移残差 | 旋转残差 |
|---|---|---|---|
| A vs B | 纯平移 50 mm | 0.19 mm | 0.013° |
| **A vs C** | **原地旋转 15°** | **0.71 mm** | **0.038°** |

### 19.3 为什么旋转那一组才是手眼验证

```text
纯平移：board_base = T_base_tcp @ T_tc @ T_cam_board，
        T_base_tcp 只变平移 ⇒ 差值恒等于平移量，与 T_tc 无关
        → 只验证了"TF/运动链"，验证不了手眼
旋转：工具姿态变了，T_tc 的误差会随姿态转过去 ⇒ 差值里才出现手眼误差
        残差 ≈ |δ| · 2sin(θ/2)，θ=15° → 2sin7.5° ≈ 0.26
        ⇒ |δ| ≈ 0.71/0.26 ≈ **2.7 mm**（手眼平移误差上界）
```

结论：**手眼链可用**——口径正确（上一节），差分量级 ≤ ~3 mm / ≲0.05°。
注意这是"差分上界"，不含板尺寸本身的系统偏差（板 25 mm 已知、重投影 0.05 px 已佐证内参与板参数正确）。

### 19.4 影响

```text
· 相机系 → base 系现在可以用来驱动机器臂（误差 ≤3 mm 量级，低于精观测位 45 cm 处的容差）；
· 下一步可以用 fine_view.json 里的精观测位真正移动 + 重采。
· 若要更准（亚毫米），需要更长的基线/更大转角做多姿态最小二乘标定（当前未做）。
```
