## 2. 断联排障：三层结构（今天最大的时间消耗，也是最大的收获）

```text
"反控端口 50001/50003/50004 一条都没有" 有三种完全不同的原因：

① 物理层  ping 机器人：50 包只回 12 个 → 76% 丢包
          驱动日志刷屏 PrimaryPort ... End of file
          处置：换交换机端口 → 0% 丢包
② 连接层  丢包修好后端口仍为 0
          原因：主端口连接已在丢包期间被打断，网络恢复不会自动重连
          处置：重启驱动栈 → 端口恢复 3 条
③ 应用层  端口 3 条 ESTAB、task_running=true、速度滑条 100%，
          但机械臂接受目标后 10 秒无位移（NO_MOTION）
          处置：同样只能重启驱动栈（重新上传并播放 external_control 程序）
```

补充一层今天新发现的：

```text
④ 主机防火墙  Windows 以太网被判为"公用网络"→ 阻止入站
             证据：从 Windows 本机 Test-NetConnection 192.168.1.100:50001 → False
             处置：网络改为"专用"或放行 50001/50003/50004
```

**排障顺序（写入手册第 25/26 条与 agent_memory）**：

```text
ping 机器人 50 包 → ping 相机做同网段对照 → 看驱动 PrimaryPort 错误
→ 全正常才怀疑"程序没启动" → 网络好了端口仍 0 → 重启驱动栈
```

## 3. RVS 预算：三次迭代才对

| 版本 | 问题 | 修正 |
|---|---|---|
| v1：单次超时 60 s × 最多 6 次 | 5–6 分钟 | 引入总预算 60 s |
| v2：总预算 60 s（壁钟） | 机械臂移动把预算吃光，到基线 B 已"预算耗尽"，T2 根本没触发 | 预算只累计【触发等待时间】 |
| v3：等待预算 + 按剩余次数均分 | 基线 A 用光预算，B 仍被跳过 | 每次 = 剩余等待预算 / 剩余尝试次数（下限 6 s） |

实测（19:25 那次）：T1 3.8 s、T2 基线 A 两次共 18.3 s，远低于 60 s，且**基线 B 有机会**。

## 10. 装配策略：从口述到代码

所有者口述（当天入手册第 23 条，11-07 又补充了手动流程）：

```text
① 初始插入阶段可让工件绕 TCP 的 Y 轴小幅转动，以获得较宽松的区域
② 随深度增加，可转空间减小，末段应仍保留约 1.5° 的转动空间
③ 插入过程中检查 Y 轴两端间隙，正常左右各约 2 mm
④ 必须"边转边插"，直接插入会让空间越来越小、阻力越来越大直至插不动
⑤ 需检查左右间隙是否平衡，否则最后"绕 TCP 转 10°"环节阻力会大很多
⑥ 判定到底后沿 Y 左右横移（每步 1 mm，共 ±2 mm）
```

代码落地（`scripts/teaching/assembly_search.py`，提交 f665b4d / 1187919）：

```text
· 旋转为【右乘】：attitude * Ry(θ)，即绕 TCP 自身 Y 轴，TCP 点固定、工件远端摆动
  （与师兄 T_world_insert @ T_rot 同一约定）
· 振幅起始 2.0°，末段下限 1.5°
· 每步打印 y 方向相对名义插入轴的漂移，超过 1 mm 标注 "Y UNBALANCED"
· 软件不因力矩取消动作（只记录），只有示教器保护能停
· 开头有 --expect 位姿门（2 mm / 0.5°），防止在错误位姿上开始插
```
