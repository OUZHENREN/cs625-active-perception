# 2026-10-24 PLAN — 工件分割模型重训方案（可实施）

> 目标：把"掩膜粘连桌面"这个长期问题一次性解决，并让掩膜分辨率与训练/推理一致。
> 现状证据见 `2026-10-23_WORKLOG_FINE_ICP_QUALITY.md`。

---

## 1. 为什么必须重训（量化的问题）

```text
· 观测点云离群点率 26%：掩膜把工件下方的木桌一起框进来
· 精阶段 ICP 覆盖率因此被压到 70–96%（同一正确位姿会抖动，甚至判 FAIL）
· 训练分辨率 1280×960，推理却用 imgsz=640 → 掩膜边界系统性内缩
· 训练集缺少"近距占满画面"与"空场景"样本，模型只会做"大锅里挑工件"
· 多视角实验显示：视角一斜（+40°）掩膜更容易把背景吃进来
```

**注意**：现在的问题不是"认不出工件"，而是"边界不准 + 负样本不足"。
所以重训的重点是**负样本 + 近距样本 + 分辨率一致**，而不是无脑加正样本。

## 3. 标注方案（自动化为主，人工只修边界）

### 3.1 用 ICP 位姿 + CAD 投影生成精确掩膜（我们已有这个能力）

```text
输入：彩色图 + 深度图 + 该帧的 TCP 位姿 + 手眼常量 tcp_to_camera.json + CAD 模板
步骤：
  ① 用现有 icp_pose_once.py 算该帧工件位姿（多帧共识，保证正确支）
  ② 把 CAD 顶点按位姿投影到图像（含深度遮挡测试：模型点被实测表面遮挡则剔除）
  ③ 得到像素级掩膜 → 转 YOLO-seg 多边形（cv2.findContours，approxPolyDP）
  ④ 自动生成的掩膜与该帧的 YOLO 预测做 IoU 比对，IoU<0.8 的挑出来人工修
```

优点：标签来自几何，不受现有模型偏见影响，**边界天然精确**；
负样本不需要标注（YOLO 的 seg 任务中无目标的图就是空标签）。

### 3.2 人工修正量估计

```text
自动标注预计可用率 70–85%，需要人工修的约 100–150 张（主要在遮挡与反光帧）
工具：labelme / AnyLabeling / CVAT 任选，导出 YOLO-seg 格式
```

## 5. 训练配置

```text
基础权重：~/cs625_yolo_seg/runs/segment/runs/box_seg640/weights/best.pt（从现有模型微调）
模型：yolov8n-seg（先）→ 若边界仍抖，换 yolov8s-seg
imgsz：1280（与采集/推理一致，不再用 640）
epochs：120，patience 30
batch：8（1280 下显存不够就 4，配合 amp）
优化器：SGD lr0=0.01（微调用 0.003），cos_lr
增强：hsv_h/s 0.5、hsv_v 0.4、flipud 0.0、fliplr 0.5、mosaic 0.5、scale 0.3
注意：mosaic 对小目标有利，但我们的工件常占满画面 → mosaic 用小一点
```

命令：

```bash
cd ~/cs625_yolo_seg
yolo segment train model=runs/segment/runs/box_seg640/weights/best.pt \
  data=datasets/2026-10-25/data.yaml imgsz=1280 epochs=120 batch=4 amp=True \
  lr0=0.003 cos_lr=True patience=30 project=runs/segment name=box_seg1280
```

## 6. 验收标准（模型指标 + 下游指标，缺一不可）

| 指标 | 现状 | 目标 |
|---|---|---|
| val mask IoU (box class) | 待测 | ≥ 0.90 |
| 掩膜边缘与工件轮廓偏差 | — | ≤ 5 px @1280 |
| 空场景误检率 | 待测 | < 2% |
| **ICP 观测点离群率** | **26%** | **≤ 8%** |
| **ICP 覆盖率（单视角）** | **70–96%** | **≥ 90% 且波动 ≤ 3%** |
| 单帧推理耗时 | 640 下 ~27 ms | 1280 下 ≤ 60 ms（CPU）/ ≤ 15 ms（GPU） |

**下游指标才是最终目的**：模型指标再好，如果 ICP 的离群率没降下来，就不算成功。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 自动标注的位姿错支 → 掩膜错 | 只对"3 帧共识通过"的帧自动标注，其余跳过 |
| 1280 训练显存不足 | batch=2 + amp + 梯度累积 |
| 新模型过拟合单个场景 | 按场景划分 + 负样本充足 |
| 重训后 ICP 反而变差 | 用第 6 节的表做 A/B，不达标就回滚 |
| 依赖升级风险（本次已踩） | **不要动 numpy/opencv 主版本**；训练在独立虚拟环境跑（`~/venvs/yolo`），推理仍用系统环境 |

## 10. 与"视角鲁棒性"的关系

新掩膜只解决"边界脏"，**不解决 +40° 的四重对称歧义**。
后者要靠：①锚点定支升级为硬门禁；②或在 GPU 上跑 PPF/FoundationPose。
两件事并行推进，不要混为一谈。

## 11. 类别体系修订（2026-10-24 所有者意见）

原方案把所有背景都当"负样本"，这是错的：**两张桌子是碰撞规划要用的结构**，
必须单独成类，不能与"完全无用的幕布"混在一起。

```text
类别 0  workpiece    工件（几何投影标注：CAD + 已知位姿）
类别 1  slot         插槽（几何标注：已知位姿的 3D 包围盒）
类别 2  worktable    工件桌台面（平面拟合 + 区域约束 x < 1.05）
类别 3  slot_table   插槽桌台面（平面拟合 + 区域约束 x > 1.05）
类别 4  curtain      幕布（竖直面 y > 1.15）—— 这才是真正的"无用负样本"背景
```

这样训练出的分割结果可以直接喂给：
- **碰撞规划**：worktable / slot_table 的掩膜 → 深度反投影 → 桌面碰撞面；
- **感知**：workpiece / slot 掩膜 → 位姿解算，且不再把桌面吃进工件掩膜；
- **背景抑制**：curtain 掩膜用于排除。

### 现状与依赖

对当前 7 帧场景模型做平面拟合，只稳定得到：
```text
水平面 z ≈ -0.10（工件桌面）
竖直面 y ≈ 1.25–1.44（幕布，多个折面）
```
**插槽桌面没被拟合出来**——因为已采的帧几乎都对着工件/幕布，插槽桌只是远景边缘。
所以：类别 2/3 的平面参数必须等**环境宽视角帧**（阶段 3，已排队）采完后才能拟合准确，
再回头统一标注。这也是为什么环境采集不是"随便拍几张背景"。

### 标注顺序（定稿）

```text
1. 工件批次  -> 类别 0（CAD 投影）
2. 插槽批次  -> 类别 1（3D 包围盒投影）
3. 环境批次  -> 先拟合 worktable / slot_table / curtain 三个平面
4. 全量标注  -> 0/1/2/3/4 五类掩膜
5. 训练      -> yolov8n-seg, imgsz=1280, 从 box_seg640/best.pt 微调
```

## 12. 两条采集/标注前提（2026-10-24 所有者明确）

### 12.1 只采正面，不采背面

```text
工件总是以"带扶手的一面"朝向机械臂（这是抓取方式决定的），
背面不会被看到，采集时不需要绕到背面。
→ 方位角限制在正面 ±25°，俯仰 ±12°，与现有安全工作盒一致。
```

### 12.2 工件位姿不是固定的

```text
工件在工作台上可以被摆放到不同位置/朝向，位姿不是常量。
因此：
· 不能用"某个固定位姿"去标注任意新帧；
· 当前这批训练帧之所以能用固定位姿标注，是因为【采集期间工件没有被移动】，
  这是采集会话的约束，不是系统的前提；
· 系统运行时的正确定位链路是：每帧独立 ICP 解算（icp_pose_once.py 已有），
  不能把位姿当成配置常量。

标注脚本 auto_label_frames.py 因此需要两种模式：
  --part-from-fixed   采集会话内工件静止（快，当前用这个）
  --part-from-icp     逐帧解算位姿（慢，工件会移动时必须用这个）
```

### 12.3 对训练数据的影响

```text
· 训练帧的位姿标注用固定值即可（工件未动）
· 但训练样本的【视角多样性】必须覆盖工件被摆在不同位置的情形：
  因为真实场景中工件位置未知，模型要能在任意位置检出工件。
· 所以采集时要"移动工件本身"（换个摆放位置/角度），而不只是移动相机。
```
