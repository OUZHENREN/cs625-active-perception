> **存放位置**：`docs/manuals/`（与 `docs/worklogs/` 分开；Obsidian 同步到 `01_研究规划`）。

## 1. RVS 报「TCP 等待连接时间超时」

```text
症状：RVS 界面红字「TCP 等待连接时间超时」；我们这侧触发后完全没应答
真因：RVS_AI_Center 没连上（不是相机问题、不是网络问题、不是端口问题）
处置：以【管理员方式】重新启动 RVS_AI_Center
确认：tasklist.exe | grep -i "RVS_AI_Center"  应能看到进程；端口 2024 OPEN
预防：每次开始视觉作业前先确认 RVS_AI_Center 在跑
```

**为什么它会导致"没有位姿"**：RVS 的粗匹配需要 AI 提供 2D 种子，AI 掉线 → 粗匹配无输入 →
直接返回 `NG,POSE,0,0,0,0,0`。

## 2. 客户端 `no answer after N s`（RVS 其实回了）

```text
症状：rvs_pose_client 打印 "no answer after 45s"，但 RVS 窗口没报错
真因：RVS 回了 'NG,POSE,0,0,0,0,0'（位姿未找到），
     师兄的 tcp_server 只解析 S*/R* 开头的报文，
     日志里只有一行 WARN "Unknown msg type: 'NG'"，然后什么也不发布。
确认：看 tcp_server 的输出里有没有 'NG,POSE'
     （这也是为什么客户端超时先怀疑 RVS_AI，而不是网络）
处置：先解决第 1 条（RVS_AI），或改善取景（见第 10 条）
```

## 3. 规划一律 99999 失败

```text
症状：plan_joint_locked 返回 plan code 99999 / points 0；
     换 IK 种子、给已验证关节角都没用
真因：手动拖动把腕关节绕成累积角，超出 URDF 限位 ±360°
     例：wrist_1 = −424.9°、wrist_3 = +462.8°
     MoveIt 的关节空间被限位约束，起始状态在范围外 → 规划器直接失败
确认：读出关节角，与限位比对（肘 ±180，其余 ±360）
处置：在示教器/自由拖动下把超限关节拨回 ±180 内
     技巧：跨过 ±360 时读数会自动归零，所以只需拨"剩余那几十度"，不是拨一整圈
预防：① 尽量用程序移动，少用手拖；
     ② 手拖之后先读关节角，确认都在 ±180 内再开始作业
```

## 4. 保护停止后臂不动（状态话题却全绿）

```text
症状：控制器接受了目标，臂一动没动，执行器报 NO_MOTION；
     safety_mode=1、robot_mode=7、arm_controller=active 全都正常
真因：反控通道（50001/50003/50004）被机器人侧关闭
     （保护停止会终止机器人上的 external_control 脚本）
确认：ss -tn | grep -E ":5000[134] " 应有 3 条 ESTAB
处置：bash scripts/recover_control.sh          # 轻量：只重发脚本 + 恢复速度滑条
     （不要用完整版，见第 5 条）
预防：执行器已内置"NO_MOTION 且端口不在 → 自动重发并返回码 10"；
     但保护停止后 60 s 内禁止自动重发（见第 7 条）
```

## 5. 恢复后臂下沉 / 位置漂移

```text
症状：执行 recover 之后 TCP 突然低了十几毫米（实测 0.5605 → 0.5441）
真因：完整恢复脚本会 deactivate + activate 控制器，伺服瞬间释放，
     负载下臂会自由下坠一点
处置：默认只用 scripts/recover_control.sh（轻量，不动控制器）；
     scripts/recover_control_full.sh 仅在轻量恢复无效时使用，
     且空载或有人扶稳时才允许
预防：携带工件时绝不调用完整恢复
```

## 6. 力矩值突变到 0

```text
症状：静止时 Σ|effort| ≈ 0.46（承载 6.8 kg 工件时绝不可能）
真因：控制器切换（deactivate/activate）后 effort 状态接口丢失数据
处置：重启驱动栈（SIGINT 停 launch 进程组 → 重新 launch → 激活控制器）
确认：静止时 Σ|effort| 应 ≈ 15.8（空载+工具），远大于 0
预防：执行器已内置 EFFORT_DEAD 门：力矩峰值 <1 时拒绝运动（exit 11）
```

## 7. 保护停止后"恢复—重试"导致连续碰撞

```text
症状：一次碰撞后连续 2–3 次撞在同一处，越撞越重
真因：保护停止 = 物理事件（撞到了东西）+ 反控掉线；
     自动重发 + 自动重试等于"闭着眼再撞一次"
处置（已固化为规则）：
     ① 保护停止后 60 s 内禁止自动重发重试（执行器已实现，写 /tmp 标记）
     ② 序列层遇到 exit 9/11 一律终止，不重试
     ③ 人工先看现场：撞到的是什么？为什么？
预防：接近高风险区域（夹具/插槽）前必过 13b 位姿门 + 包络门
```

## 8. 手动微动后抓取姿态歪掉

```text
症状：手拖/微动过关节后，去抓工件时夹爪歪着，蹭到工件把手
真因：手动动过关节但没人复验 TCP —— 曾出现位置只差 4.3 mm、姿态差 12.09°
```

## 16. RVS 测量极不稳定，一次触发靠不住


## 19. 改预插入位姿必须同步改插入位姿

```text
预插入与插入是同一条链条上的两个点：
  insert = 槽位姿 × T_s_tcp
  rotated = insert × Ry(−10°)
  pre_insert = rotated 沿自身 z 后退
只改起点不改终点 → 相对几何被破坏 → 下降方向不再指向槽口 → 反复碰撞。
允许的一致性关系只有三种：整体刚性平移 / 只改高度 / 改倾斜角重新推导。
每次改完必须打印两个位姿并回算校验（误差应为 0.00 mm）。
```

## 21. 装配公差极紧：372 mm 不是物理意义上的底部


## 33. 绝对不要用 `ensure_robot_ready --force` 来"同步"手动拖过的机械臂

```text

  · 手动拖过机械臂后，**不要**执行 ensure_robot_ready --force / recover_control.sh；
  · 直接下发一条**从当前实测位姿出发**的新轨迹即可 —— execute_assembly_chunks 的
    FIRST_POINT_FAR 检查保证轨迹起点与实测位姿相差 ≤0.03 rad，因此不会跳变；
  · 确需重挂时，先手动把机械臂摆回"最后指令位姿"附近（差 ≤2°）。

已固化的硬闸：
  · execute_assembly_chunks 每次成功执行后写 runtime/last_commanded_pose.json；
  · ensure_robot_ready --force 会先比对"当前实测 vs 最后指令位姿"，
    偏差 >2° 直接拒绝并打印原因（退出码 5）。
```

## 36. WSL 系统时钟往回跳：机械臂"卡住/摆动"与测量不稳的真正元凶

```text
症状（2026-11-20 傍晚起，越来越频繁）：
  · 轨迹执行到一半停住不动，几秒后突然加速追上；所有者描述为"到位后不停、来回摇摆"

  · 同一位置的覆盖率在 0.86–0.98 之间乱跳，重复性时好时坏

根因：WSL 的系统时钟被反复往回拨
  · dmesg 累计 1235+ 次 "Time jumped backwards"
  · 实测 30 秒内出现 4 次倒退，**最大一次 5526 毫秒（5.5 秒）**
  · 我们的轨迹只有 6 秒长 → 执行期间必然遇到时间倒退
  · 控制器按 ROS 时间戳推进轨迹，时间倒退 → 它停在原地"等时间追上"→ 恢复后再跳

更隐蔽的连带影响：测量流程靠时间戳配对彩色帧与深度帧。
  时钟一跳，配对错乱 → 点云错位 → 覆盖率与姿态估计随机变差。
  同一相机位姿在修好时钟前后：0.887（REFUSE） → 0.972（3/3 可信）。

为什么重启 timesyncd 反而更糟：
  WSL2 里有两个时间调整者 —— Hyper-V 的 TimeSync（从 Windows 主机同步）
  和 systemd-timesyncd（从 NTP 服务器同步）。两者互相拉扯就是反复跳变的来源。

规矩（2026-11-20 所有者执行）：
  1. WSL 里**关闭** systemd-timesyncd，只留 Hyper-V 主机同步：
         sudo systemctl disable --now systemd-timesyncd
  2. 验证（必须满足才允许跑轨迹）：
         python3 - <<'EOF'
         import time
         prev=time.time(); worst=0
         for _ in range(300):
             time.sleep(0.1); now=time.time()
             worst=max(worst, prev-now); prev=now
         print(f"最大倒退 {worst*1000:.0f} ms")
         EOF
     判据：**0 ms**（小于 100 ms 才可接受）。
  3. 时钟不稳时不要下运动指令——所有"机械臂不听话"的现象先查这一项：
         dmesg | grep -c "Time jumped backwards"

判据速查：如果机械臂运动是"连续匀速"的，时钟正常；如果表现为"停—冲—停"，
先查时钟，不要怀疑规划和轨迹代码。
```

## 38. 示教位精拍的完整流程与验收标准（2026-11-20 一晚拍完 9 个角度的做法）

```text
目标：工件每转一个角度，就有一个"站位（相机 TCP 位姿）"被验证可用，
      以后换视角时直接查表，不再现场找位姿。
本日成果：+27 / +23 / +18 / +13 / 0 / −9 / −19 / −29 / −36（全部覆盖率 ≥0.95、3 组可信）
```

### 五步流程

```text
① 粗观测：在上一站位（或粗观测位）读当前工件 yaw 与位置
     python3 scripts/measure_object.py --preset workpiece --stage coarse --groups 3          --out runtime/measurements/workpiece_at_<角度>_coarse.json

② 推导相机位：用**同一时刻**的"工件位姿 + 相机位姿"做完整刚体变换
     python3 scripts/derive_from_station.py --current <粗测.json> --plan
   （默认从质量最好的锚点推导，误差不累积；--strategy nearest 用角度最近的站位）

③ 移动：必须经 plan_pose_ik 与 execute_assembly_chunks（自动分段 + 逐段碰撞校验）
     python3 scripts/execute_assembly_chunks.py <推导出的计划.json>

④ 精观测：3 组
     python3 scripts/measure_object.py --preset workpiece --stage fine --groups 3          --out runtime/measurements/workpiece_at_<角度>_fine.json

⑤ 登记（覆盖率 <0.95 会被自动拒绝）
     python3 scripts/add_station_from_measurement.py          --measurement <精测.json> --key '0@20261120' --yaw <实测yaw> --write
```

### 验收标准（硬性）

| 指标 | 门槛 | 说明 |
|---|---|---|
| 覆盖率中位 | **≥0.95** | 0.90–0.95 只算"可接受但证据偏弱"，**不得**登记为示教位（所有者 2026-11-20 定） |
| 可信组 | 2/3 可接受，3/3 最好 | 2/3 时**先重测一次**再考虑调位姿：今天有两次重测即变 3/3 |
| 平移重复性 | ≤1.0 mm | 超差说明视角对该角度不稳定 |
| 姿态重复性 | ≤0.5° | 超过 2° 基本可判定视角不可用 |

### 关键经验

```text
· 绕工件"角点"旋转不影响推导：刚体变换里 (x → R(x−P)+P) 的 P 会被消掉，
  前提是两次测量用的**是同一个参考点**（都是测量出的 CAD 原点）。
· 必须用**同一时刻**的工件位姿算相对向量。混用不同时刻会掉到 0.88（今天踩过）。
· 轨道法（只绕 Z 转 Δyaw）是完整变换的一阶近似：两者今天只差 1.3 mm，
  但工件一旦有倾斜就必须用完整变换才能吃掉 tilt。
· 推导位姿**经常不可达**（腕部会折进前臂，实测 −19°、−45° 都 IK 无解）。
  不可达时最快的做法是**所有者手工摆位**：−19° 手摆后 0.975/3-3，
  比任何自动推导都好。
· 扶手分（handle_score）掉到 0.1 以下 = 带扶手那面转到了侧向，
```


## 67. 插入位姿应该像抓取一样做一次相对标定（建议方案）

```text
为什么建议重标（所有者 2026-11-25 问"要不要像工件抓取那样重新标定插入位姿"）：
  抓取已经有 `grasp_in_workpiece_frame`：{T_工件实测 @ T_rel}，与坐标系约定无关，
  工件移动后自动跟随，这也是 11-24 抓取能一次成功的原因。
  插入没有对应物：insert / pre_insert 始终是**绝对位姿**，靠"经验平移 45.5 mm"对出来，

建议的标定步骤（与抓取标定同构，真机 + 所有者在场）：
  1. 所有者手动摆出**能干净插入**的位姿（工件在夹爪里、插到底、座好），确认后可抬起退出；
  2. 记录三样东西：
       · TCP 位姿（/tcp_pose_broadcaster/pose 的 xyz+quat）
       · 六个关节角（/joint_states）
       · 同一时刻的插槽测量（measure_object --preset slot --stage fine → T_base_slot）
  3. 计算相对变换：
       insert_in_slot_frame = inv(T_base_slot) @ T_base_tcp
     （与 grasp_in_workpiece_frame 完全同构，写进 config，往返校验应为 0.000 mm）
  4. 之后插入目标一律 = T_base_slot(当次实测) @ insert_in_slot_frame，
     效率模式与示教模式共用；pre_insert / straighten 由它再按 −10°/+100 mm/回退 10 mm 派生。

这样做的两个直接好处：
  · 再也不需要争论"哪个绝对坐标对"，因为比较的始终是同一个相对变换；
  · 插槽夹具若被移动或重新安装，插入目标会自动跟随（就像工件移动后抓取自动跟随）。

验收线（与抓取标定一致）：
  · 往返误差 0.000 mm（T_slot @ T_rel 复原记录的 TCP）；
  · 记录时的六个关节角与日后推导出的目标做 IK，解应落在同一构型分支；
  · 标定后先 --plan-only 跑一遍插入链，确认三个位姿与手动摆位一致再真机执行。
```


## 68. 插槽位姿是"面内弱约束"：同一片点云两条路径差 66 mm

```text
背景（所有者 2026-11-25 的客观事实）：
  · RVS 测的插槽位姿曾支撑过插入（9 月虚拟机 + 师兄程序、10 月底复现）；
  · 但示教模式改用 RVS 最新一次测量后，工件在 **X 方向大幅偏置**导致插不进去（有日志）；
  · 11 月所有者手动摆出的位姿是最近最准的一次，但已过半个月，不再可靠。

  先验引导 + ICP（现在用的）  → (1.2562, 0.1419, 0.4428)

  工件的三平面 + 扶手特征强约束，所以工件测量稳定（0.42 mm / 0.078°）。

所以：
  · 插槽的"绝对位姿"本身不是良定义的量 —— 争 37/42/48 mm 没有意义；
  · 必须换成**角点锚定**（三平面交 = 角点，或角点初值 + 禁止面内滑移的受约束 ICP）；
  · 再用一次手动标定得到 `insert_in_slot_frame` 相对变换（见第 67 条）。

验收线：三条组重复性 ≤ 2 mm（现在 z 方向 19 mm，未达标）；往返 0.000 mm；已知平移跟随测试。
详见 docs/reference/task_pose_derivation.md §6（"我们自己的位姿标准"）。
```

## 71. 估算末端弯矩：353 mm 是竖直的，质心要用体素化算，实测 effort 不能反推量程

```text
背景（2026-11-26）：为确认 KWR75D（Mx,My,Mz 额定 18 N·m）能否承载 7 kg 光学模块，
我先后给出"超额定 2.9×"和"超 7.5×"两个结论，**两次都错**，所有者两次纠正。

错误一：把 flange→TCP 的 353 mm 当成水平力臂
  · 353 mm 是**工具轴向长度**（竖直向下），不产生绕法兰的弯矩；
  · 只有质心相对法兰的**水平分量**才产生弯矩。

错误二：用 CAD 包围盒中心当质心
  · 工件是空心件（实体体积 6349 cm³，若 7 kg 则等效密度 1103 kg/m³）；
  · 正确做法：**体素化求质心**（o3d VoxelGrid，5 mm → 50793 体素，质心取占用体素中心均值）；
  · 本例真实质心在 CAD 系 [-0.2059, 0.0688, -0.0114]，相对抓取点只有 (2.8, 42.2, **-190.8**) mm
    —— 质心几乎在抓取点正下方（因为夹在顶部把手上），**水平力臂只有 42 mm**。

正确结论（7 kg、当前抓取模式）：
  静态弯矩 = 7 × 9.80665 × 0.042 = **2.9 N·m**（额定 18 → 0.16×，过载 54 → 余量 18.6×）
  轴向力   = 69 N（含夹爪 4.58 kg 共 114 N；Fz 700 → 余量 6.2×）
  → KWR75D **完全够用**。

为什么"实测力矩"不能用来反推量程（重要）：
  · 归档 timeseries.csv 里确有 joint_effort_1..6，但量级不自洽：
    腕关节中位只有 0.2–0.6 N·m，而仅夹爪 4.58 kg（质心距腕约 0.1 m）就该有约 4.5 N·m；
  · 同一批数据里还出现过 730 N·m 的离群值；
  · 结论：驱动上报的 effort 不是可直接当"关节输出力矩 N·m"用的量（可能有缩放/未标定），
    **只能用来判断"力矩是否活着"（Σ|effort| ≈ 15.8 不是 0），不能用来做绝对量校核**。

预防：
  ① 估弯矩先画受力图，明确"哪个方向的分量产生弯矩"；
  ② 质心一律从 CAD 体素化/质量属性取，不用 bbox 中心；
  ③ 任何"实测力矩反推"之前，先用一个已知量（如夹爪自重及其力臂）验证该通道的量级是否自洽。
```

```text
     → 工件测量有"扶手特征"做锚（重复性实测 0.42 mm / 0.078°），
       插槽测量**什么都没有**，纯靠 ICP。
  ② **模板是碰撞网格**：slot preset 用 slot_fixture_collision.stl，
     碰撞体通常是简化几何（楔形/滚轮细节丢失）→ 配准只能靠大平面。
  ③ **大平面 → 面内 3 个自由度无约束**：沿长轴的平移、绕法向的旋转在代价面上几乎是平的，
     噪声（组间 0.4–1.9 mm）决定它滑到哪。
     已记录：ICP 沿长轴滑移 **104 mm**（docs/reference/simulation.md:178，近对称楔形）；
     同一片点云两条配准路径差 **66 mm**（手册第 68 条）。

→ 观测到的 40 mm 落在这个 66–104 mm 的滑移带内，**多测取平均不会收敛**。

处置（2026-11-26 起）：改用角点锚定——三平面求交得到角点，2 角点 + 1 法向定义插槽坐标系，
每个自由度都有几何锚点。原型 scripts/slot_corner_anchor.py（离线跑已有数据集）；
实测发现**槽壁法向是 ±x 不是 ±y**（通道沿另一方向延伸），分类器已按此修正。

预防：插槽类"大平面 + 近对称"的对象，**不要用整体 ICP 的绝对位姿驱动长行程动作**，
必须换成有物理锚点的测量（角点/棱边/特征），并用"连续 3 组 ≤2 mm、隔天 ≤5 mm"验收。
```

## 77. RVS 的 slot 原点 = 夹具顶面基准角点；插槽位姿的误差集中在 y（通道长轴）

```text
背景（2026-11-26）：插入总是差 30–40 mm，需要确认"slot 位姿到底指哪个点"。

已核实的证据（都是文件级，不靠猜）：
  ① RVS 模板 `Model/slot_pointcloud20260127.ply`（30 万点）：
       x −0.143~+0.010  y −0.430~+0.044  z −0.435~+0.000   ← z 最大恰好 0
     夹具 CAD `slot_fixture_collision.stl`：
       x −0.177~+0.023  y −0.566~+0.179  z −0.508~−0.000   ← z 最大也是 0
     → 模板是夹具的子区域、**共用同一坐标系** → **原点在顶面**
  ② 师兄 `collision_object_publisher.py:163` 的固定变换：
       T_s_tcp = diag(-1, +1, -1)  +  (−0.082, −0.193, −0.4125) m
     旋转 = 绕 y 180°（**没有任何倾角**）；平移 −193 mm 正好是模板 y 的中心
     → **插入点 = 顶面角点 + (−82, −193, −412.5) mm**

用所有者手摆的 S02.straighten([1.1649, −0.0471, 0.0285]) 反算 slot 原点：
     slot = straighten − (−0.082, −0.193, −0.4125) = [1.2469, **0.1459**, 0.4410]
  与 config 原值 [1.2416, **0.1817**, 0.4432] 相比：
     残差 = (+5.3, **−35.8**, −2.2) mm

结论：
  · x（通道宽度方向）与 z（顶面）是**强约束**，都准到 2–5 mm；
  · **y（通道长轴方向）是弱约束**——模板 y 跨度 474 mm、通道更长，配准可以沿 y 滑；
  · 所以"每次差 40 mm"实际上就是 **y 方向的滑动**，与 x/z 无关。

    `slot_origin + T_s_tcp` 能复现手摆位姿（y 残差 ≤1 mm、x/z 残差 ≤8 mm），
    并断言夹具模型原点在顶面；
  · 修正后推导插入位 = [1.1596, −0.0471, 0.0307]，与手摆位姿残差 (−5.3, 0, +2.2) mm。

预防：
  · 讨论"插槽位姿准不准"时必须分方向说——**x/z 可信、y 不可信**；
  · 任何插槽测量都要报告 y 与基线之差；超过 10 mm 时拒绝直接插入；
  · 角点锚定时应优先锚 **y 方向的两个端点**（通道两端），因为 x/z 本来就不需要锚。
```
